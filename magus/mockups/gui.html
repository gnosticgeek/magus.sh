magus as a command palette

§5 says the GUI comes later and is "a skin, not a rewrite" — it reads and writes the same manifest the TUI does. This borrows walker's visual language for that skin: a floating panel, one input, tight rows, and a 25%-alpha accent wash on the selection instead of a solid highlight.

Why a palette fits magus

Walker's core idea is many providers, one list. magus has exactly that shape: steps with a state, bundles, themes, and the four verbs.

So the GUI isn't a wizard with Next buttons — it's one searchable surface where you can both see what your machine is and change it. The wizard is just the palette with the list pre-filtered to one question.

Still a skin, not a rewrite

Every row maps to something already in the reconciler: a Step and its State, a bundle in steps.go, or a field in the manifest.

Nothing here needs new backend concepts — which is the test of whether §5's "GUI later, over the same manifest" is actually true or just aspirational.

What this is not

Not a proposal to ship walker. Its GTK4 + layer-shell + elephant dependency chain doesn't install in userland on SteamOS, and giving a launcher a global hotkey means writing kglobalshortcutsrc — the §12 tripwire.

This borrows the look. magus stays a setup tool you open, not a resident launcher that owns a key.
