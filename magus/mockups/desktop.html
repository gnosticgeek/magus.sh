What one palette actually drives

Plasma colour scheme — window chrome, panel, highlights. Written as a new colour-scheme file plus kwriteconfig6.

Wallpaper, icons, cursors — generated or shipped in ~/.local/share/magus/ and pointed at.

GTK, so flatpak apps don't look like visitors.

The terminal, via kitty's own config.

Sized for a sofa, not a desk

The panel here is taller, the fonts larger, the icons bigger and the cursor scaled up — because this screen is three metres away, not sixty centimetres.

All of it is ordinary Plasma settings. No custom shell, no replacement panel. That's the difference between a setup tool and a desktop environment.

What magus deliberately won't do

No panel replacement, no global keyboard shortcuts, no window-manager changes. §12 is explicit: we do not own the desktop session.

The layout above is stock Plasma. Every window, the panel arrangement, the two desktop icons — all exactly where SteamOS puts them. Only the appearance changed.

The LED bar is not verified. Nothing in §10 has been confirmed on real hardware, and whether the front LED is addressable from the host is unknown — it may well be firmware-locked. It's drawn here because it's the idea worth testing first, not because it's known to work. If it turns out to be locked, the planned fallback is the Steam Controller's LED plus an on-screen ambient overlay: same event plumbing, different output sink. Which is the argument for building that code as event sources → pluggable sinks from day one, so a locked LED costs a backend rather than the feature.
